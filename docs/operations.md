# 私有资料库运维

## 配置边界

所有密钥只放在本机 `.env.local` 或服务器的秘密管理系统，不提交 Git，不打入镜像。浏览器不接收百炼或 Supabase 服务端密钥。用户请求的资料查询始终使用用户会话，服务密钥仅用于额度记录、后台处理和运维导入。

`APP_MODE=preview` 只支持本地开发，生产环境会拒绝启动该模式的请求。数据样本不放入 `public/`，Docker 构建不包含 `data/`、本地配置和测试输出。`APP_ORIGIN` 是访问站点的真实来源，生产必须为 HTTPS；源检查不依赖浏览器提交的组织 ID。

## 部署

Vercel 托管网页、云服务器仅运行资料处理的部署方式，使用 `compose.worker.yaml`，见 [云端后台部署](cloud-worker.md)。下面的 `compose.yaml` 步骤适用于网页也放在服务器上的完整部署，不要在已有 Vercel 网站的机器上额外启动重复网页服务。

1. 使用干净机器，安装 Docker Engine / Compose，准备域名、TLS 和 Supabase/百炼环境变量。中国大陆访问爱尔兰项目的连通性需用实际网络验证。
2. 按用户要求，Supabase 保留公开注册和邮箱确认；新账号不会自动加入已有资料空间。完成本人 Auth 账号和 `bootstrap:owner`。项目已迁移时不要再执行 `schema.sql`。
3. 将 `.env.local` 中 `APP_ORIGIN` 设为自己的 HTTPS 地址、`APP_MODE=connected`。确认两个密钥均配置。
4. `docker compose config --quiet` 校验配置（不要输出完整配置到日志，以免打印密钥）。
5. `docker compose build`，随后 `docker compose up -d`。网页端口只绑定宿主机回环地址；按 `deploy/nginx.conf.example` 配置 TLS 反向代理。
6. 检查 `/api/health`、登录、只读检索、一次带引用的真实问答和一份小文件的上传审核。健康端点只检查进程与配置，不证明外部模型/数据库可用。

当前构建的是模块化单体和一个处理器，无需 Kubernetes、消息中间件或多微服务。ClamAV 初次下载病毒库需要时间和内存；没有可用扫描器时文件处理会失败关闭，不能跳过扫描上线。

## 发布与回滚

保留上一个应用镜像的 digest，发布新版本时先在隔离环境核对数据库迁移。采用向后兼容的新增列/表迁移；涉及删除或变更数据时先备份。回滚应用镜像不能撤销数据库变更，不要自动执行破坏性 down migration。

远端已应用迁移由 Supabase 记录。仓库 `supabase/migrations/` 是可复现来源，本地数据库合同测试按顺序应用这些迁移。`schema.sql` 仅保留早期快照，不能用于新环境部署或重复应用到已初始化的数据库。

删除资料会将其移入回收站，保留原文件、译文与索引，并排除在新检索和问答之外。恢复时保留删除前的已发布或待审核状态；处理中被删除的任务恢复为失败状态，需要手动重试，避免恢复动作自动产生模型费用。

生产镜像应保存通过验证的镜像 digest；容器基础镜像、系统安全补丁和病毒库按维护计划更新。Node 依赖和 Python 直接依赖已锁版本，Node 有完整 lockfile。更新时只运行与变动相关的检查。

## 任务恢复

- 上传成功后状态为 queued；worker 原子领取并取得 5 分钟租约，长任务周期续租。
- 中断的 processing 任务会在租约过期后重新领取，最多 3 次。旧租约持有者不能写入结果。
- 解析、扫描或模型失败显示简短错误码；不把完整输入或密钥写入日志。
- 成功后状态为 review，人工检查中英内容与原文件，再发布。
- 归档立即退出检索；归档同时撤销处理租约，旧 worker 不得恢复它。
- 孤立的 uploading/archived 原文件不自动删除，避免误删。确认不再需要后由运维按文档 ID 清理数据库记录和私有桶对象。

翻译与向量缓存按空间、内容哈希和模型名隔离。模型请求默认不自动重试，防止超时后重复计费；失败后人工重试会复用已完成的缓存。

## 用量

默认问答模型 qwen-plus 非思考模式，单次输出最多 1200 token，证据文本最多 16,000 字符，最多 6 个片段；短历史有上限。问答开始原子预留 80,000 token 的保守上限，成功后按实际值结算。用量未知的错误保留预留，避免通过失败请求绕过预算。

默认每个空间每日 200,000 token（北京时间日期），每个用户每分钟最多 12 个问答预留。额度表在并发事务内更新。额度是 token 控制，不是人民币账单；实际费用以百炼账单为准。

管理员可在数据库修改 `cpv_organizations.daily_token_limit`。需要释放异常预留时，应先核对百炼账单与请求时间，由运维调用 service-only `cpv_settle` 记录实际消耗，不能直接清空使用量。

修改 `BAILIAN_EMBEDDING_MODEL` 必须重新索引所有需要语义检索的文档。函数只匹配当前模型名的向量，1024 维保持一致。建议稳定运行后使用经过验证的模型快照名，避免别名更新带来的变化。

## 备份与恢复

数据库备份、Storage 文件备份和环境密钥备份是三件不同的事。不要假定数据库备份包含私有桶中的文件。

- 每日备份项目表、函数和策略，频率按可接受的数据损失调整。
- 单独同步 `cpv-originals` 私有桶，记录对象路径和 SHA-256；备份应加密并限制访问。
- 保留现有原始学习资料和独立 HTML，它们可用于重建初始语料。
- 环境密钥单独保存在密码管理器；泄露后轮换百炼和 Supabase 服务密钥。
- 恢复演练在独立测试项目进行：恢复表/策略与文件，创建测试账号，验证登录、资料数量、原文定位、文件摘要和拒绝未授权访问后再切换。

不在没有实际演练的情况下承诺 RPO/RTO 或 SLA。Supabase 套餐备份能力由账户实际配置决定。

## 安全顾问提示解释

`cpv_processing_cache` 和 `cpv_reservations` 故意启用 RLS 而不创建普通用户策略，且撤销 anon/authenticated 权限；这是 service-only 数据。

`cpv_role`、`cpv_create_document`、`cpv_document_action` 是有明确用途的 SECURITY DEFINER 函数：固定 search_path，角色来自数据库，检查当前用户的空间权限，限制操作范围。安全顾问会提示它们可被登录用户调用，这属于经过审查的设计，不等于可绕过权限。单人版不向登录用户开放 `cpv_set_member`。

此项目没有经过第三方渗透测试或合规认证。复杂表格/OCR 正确性、真实模型回答质量和国内网络质量需要在本人实际数据与网络下验收。
