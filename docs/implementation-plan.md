# CPV 企业知识库 Implementation Plan

> 使用 writing-plans 规划，executing-plans 在当前会话顺序实施，避免每个任务重复分派产生的 token 开销。

Goal: 交付可配置百炼和 Supabase 的企业内部知识库，以及可本地查看真实资料的预览。
Architecture: Next.js 模块化单体，RLS 数据库，独立 Python worker。
Spec: [design.md](design.md)

## 任务与验收

- [x] 基础与语料：独立 cpv-platform 目录、锁定依赖、迁移现有真实对照片段；9 文件/2509 句保真核对。
- [x] 安全与存储：空间/成员/资料/切片/聊天/审计/额度表、RLS、RPC、私有桶、后台租约；真实 PostgreSQL 安全测试。
- [x] 百炼与问答实现：受限检索、结构化回答、引用校验、令牌计量、异常处理；关键拒绝路径测试。
- [x] 个人界面：资料目录、搜索、对照阅读、朗读、选句提问、带引用聊天、登录、审核；不做团队管理。
- [x] 入库与部署材料：文件校验/病毒扫描/OCR/翻译/向量/审核队列、历史语料导入、Docker、配置与运维手册；解析器核心验证。
- [x] 本地集成验收：类型/构建/依赖审计，修复真实问题，交付可运行入口与明确未连接项。
- [ ] 实际环境联调：补齐密钥、创建本人 Auth 账号、授权成员、导入语料、真实模型问答、云端文件与 worker 联调。

## 重点风险

跨组织 ID 不能绕过 RLS；撤权后引用不能泄露原文；无凭据不能伪造 AI；上传压缩炸弹拒绝；模型错误不能被自动重试放大费用。生产部署禁用本地预览，读取历史资料必须通过服务端权限。
